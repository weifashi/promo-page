# 案例：一个餐饮 SaaS 官网是怎么改对的

> 三语（土耳其语 / 英语 / 中文）餐饮收银 SaaS 官网，2026-11。左列是用户原话，右列是因此定下的规则（已写进 SKILL.md）。

| 阶段 | 用户反馈 | 定下的规则 |
|---|---|---|
| 定位 | 「乱乱的、不明朗」「很幼儿科，没有大牌公司的感觉」 | 版式固定、留白充足、一屏一件事 |
| 定位 | 「官网是用来诱客的，不是用来说明事实的」 | 写感觉和结果；删元说明 |
| 卖点 | 「拍菜单开店别人也有吧？」「放别人没有的」 | 只主打独有；别人有的进功能表；纠正过头的对比 |
| 覆盖 | 「我想要的是综合的」 | 照顾整个行业的细分 |
| 文案 | 「即将推出这些都去掉」「不要『不是效果图』这类字」 | 禁用词进 qa |
| 调性 | 「太白」「很黑」 | 暖深棕高级感 |
| 素材 | 「AI 生图你自己解决不了么？你之前生成过」 | 自己生成；不要先说做不到 |
| 品牌 | 「官网像在做一家店，不是收银软件公司」 | 首屏写品类；产品家族、行业方案、公司式页脚 |
| 卖点 | 「软件自动做店铺引流，老板不用懂营销」 | 独有模块：机制清单 + 合规；不写效果承诺 |
| 视频 | 「太虚构」「能自动播放么」 | 真实录屏；静音自动播放 |
| 展示 | 「能做成 gif 么」 | 动画 WebP 循环动图 |
| 展示 | 「只有一个角落，新客户不知道展示的是什么」 | 完整一屏 + 设备框 |
| 展示 | 「为什么不加商品图」 | 示例数据带图 |
| 交互 | 「能做左右箭头滚动么」 | 产品家族轮播 |
| 首屏 | 「能一屏看完么」「大屏空白不舒服」「还是大了」 | 两栏、vw 列宽、按屏高限宽、整体缩一档 |
| 细节 | 「这个图不正常，不要犯低级错误」「滚动条也要美化」 | qa 比例检查 + 看截图；默认带滚动条样式 |
| 外框 | 「手机应该用开店页那个样式」 | 外框与产品自身预览一致 |
| 产品 | 「这里排放的地方怪怪的，先画图给我看」「再多出几个方案，放开想」 | 先画多方案原型再改；放开想就给差异大的方向 |

## 遗留项（新项目开工时对照）

- 公司信息开工时就要齐。
- 「官网已写、产品未做」清单随官网交付。
- 官网演示入口进去的示例账号，要和官网展示的一致（例如商品图）。
